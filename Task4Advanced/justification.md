# Обоснование событийного подхода — «Будущее 2.0»

## Почему Event-Driven Architecture вместо Camel + DWH?

### 1. Слабая связанность (Loose Coupling)

**Текущее состояние (Camel + DWH):**
- Apache Camel создаёт point-to-point интеграции между системами
- Добавление нового домена требует изменения маршрутов во всех связанных системах
- DWH содержит бизнес-логику в хранимых процедурах — жёсткая зависимость

**Целевое состояние (Event-Driven):**
- Домены общаются через события в Kafka — подписчик не знает об источнике
- Добавление нового домена — только подписка на нужные топики
- Бизнес-логика внутри доменов, не в шине

### 2. Масштабируемость

**Текущее:**
- DWH на SQL Server 2008 — вертикальное масштабирование (ограничено)
- Отчёты формируются часами из-за трансформаций в DWH

**Целевое:**
- Kafka масштабируется горизонтально (партиции)
- Data Lakehouse (Iceberg) — разделение storage и compute
- Dremio — распределённые SQL-запросы по потребности

### 3. Скорость реакции (Time-to-Market)

**Текущее:**
- Новая интеграция: изменение маршрутов Camel + хранимых процедур DWH → недели
- Новый отчёт: ETL-разработка + тестирование → дни

**Целевое:**
- Новая интеграция: подписка на топик Kafka → часы
- Новый отчёт: SQL-запрос к Dremio через портал самообслуживания → минуты
- Near-real-time обработка вместо batch

### 4. Надёжность и устойчивость

**Текущее:**
- Единая точка отказа (DWH) — падение DWH останавливает отчётность
- Camel — потеря сообщений при сбоях

**Целевое:**
- Kafka — дурабельное хранение событий, replay при сбоях
- Event Sourcing — восстановление состояния из истории
- DLQ — обработка ошибок без потери данных
- Независимость доменов — сбой в финтехе не влияет на медицину

### 5. Data Mesh совместимость

Событийный подход естественно ложится на принципы Data Mesh:
- **Domain Ownership**: каждый домен публикует свои события
- **Data as a Product**: события — это Data Products с контрактами (Schema Registry)
- **Self-serve Platform**: Kafka + Dremio + DataHub — платформа самообслуживания
- **Federated Governance**: Schema Registry обеспечивает согласованность контрактов

## Сравнительная таблица

| Критерий | Camel + DWH (текущее) | Event-Driven (целевое) |
|----------|----------------------|----------------------|
| Связанность | Высокая (point-to-point) | Низкая (pub/sub) |
| Масштабирование | Вертикальное | Горизонтальное |
| Time-to-Market | Недели | Часы-дни |
| Надёжность | Single Point of Failure | Распределённая |
| Добавление домена | Перестройка маршрутов | Подписка на топики |
| Аналитика | Batch (часы) | Near-real-time (секунды) |
| Data Mesh | Не поддерживает | Нативная поддержка |
