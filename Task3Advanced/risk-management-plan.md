# План управления рисками «Будущее 2.0»

## R1: Потеря данных при миграции с SQL Server 2008

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Технические
- **Меры**:
  1. Parallel Run — параллельная работа старой и новой системы 6+ месяцев
  2. Инкрементальная миграция с верификацией контрольных сумм
  3. Автоматические бэкапы перед каждым этапом
  4. CDC (Change Data Capture) через Debezium для синхронизации
- **Ответственный**: Data Engineering Lead

## R2: Несовместимость бизнес-логики DWH

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Технические + Управленческие
- **Меры**:
  1. Anti-Corruption Layer между Legacy DWH и новыми доменами
  2. Документирование всех хранимых процедур и триггеров DWH до миграции
  3. Поэтапный вывод логики из DWH в доменные сервисы
  4. Регрессионное тестирование отчётов на обеих системах
- **Ответственный**: Solution Architect

## R3: Сопротивление изменениям

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Управленческие
- **Меры**:
  1. Программа обучения для аналитиков и операторов
  2. Назначение Change Champions в каждом подразделении
  3. Пилотный проект с Quick Wins для демонстрации ценности
  4. Регулярные демо и обратная связь
- **Ответственный**: CTO + HR

## R4: Нарушение требований 152-ФЗ

- **Стратегия**: Избежание (Avoid)
- **Тип мер**: Технические + Организационные
- **Меры**:
  1. Privacy by Design с этапа проектирования
  2. PHI хранится ТОЛЬКО в сертифицированном облаке (частное/гибридное)
  3. Data Classification и тегирование PII/PHI через DataHub
  4. Шифрование at rest (AES-256) и in transit (TLS 1.3)
  5. Ежеквартальный аудит безопасности
- **Ответственный**: CISO + DPO

## R5: Vendor lock-in

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Архитектурные
- **Меры**:
  1. Cloud-agnostic инструменты (Terraform, Kubernetes, Kafka)
  2. Абстракция через IaC — смена провайдера через конфигурацию
  3. S3-совместимое хранилище (MinIO как fallback)
  4. Контейнеризация всех сервисов (Docker + K8s)
- **Ответственный**: Platform Team Lead

## R6: Рост затрат на облако

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Управленческие + Технические
- **Меры**:
  1. FinOps-практики: мониторинг и алертинг по бюджету
  2. Reserved Instances для prod-нагрузок
  3. Автоскейлинг с лимитами для dev/stage
  4. Ежемесячный TCO-ревью с финансовым отделом
- **Ответственный**: FinOps Engineer + CFO

## R7: Сложность интеграции доменов

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Архитектурные
- **Меры**:
  1. Schema Registry для контроля контрактов событий
  2. ACL на границах доменов
  3. Пилот на 1-2 доменах перед масштабированием
  4. Event Storming сессии перед реализацией каждого домена
- **Ответственный**: Solution Architect

## R8: Нехватка компетенций

- **Стратегия**: Снижение (Mitigate)
- **Тип мер**: Управленческие
- **Меры**:
  1. Программа обучения: Kafka, Data Mesh, Terraform
  2. Найм 2-3 senior-специалистов по Data Engineering
  3. Внешние консультанты на первый этап (6 мес.)
- **Ответственный**: CTO + HR
